## 1. 摘要与价值定位(诚实框架)

v1 把形状做成**编译期数据段静态描述符**(仅 `key_count` 单 qword,无键表),创建后戳入
shape_ptr@48,任何键变动单向置 0。这覆盖了 AOT  closed-world 的主流形态(字面量/类实例),
bench/prop 的固定键访问已**全命中形状 IC**。

**必须先澄清 v2 不能解决什么**:bench/prop 仍 ~8.7× vs Node 的差距**不在查找**——
四域调研确认快路已命中,差距在每次访问一次 `bl/ret` call(V8 内联为单 `ldr`)、写屏障尾跳、
装箱往返。转移链本身**不缩短快路**。(注:plan.md:76 的"非查找"判词是 P2 时代结论,
**立项前须补一轮 bench/prop 定向采样**确认 call/屏障/装箱占比,避免押错杠杆。)

v2 转移链的真实价值:
1. **字典形态动态对象**(创建后加键 → v1 永久置 0 线性扫描)获得形状与 IC 收益;
2. **原型形状维度的前置**(调研确认:prototype/classinfo 恒 shape 0,是**方法读最大盲区**;
   自编译热图 check_proto/原型键簇 ~6%、深链委托 _object_get 递归每次全扫)——方法读是
   比数据属性更大的热点,T2 原型维度才是本专项的主收益;
3. 与未来精确根/压实协同(形状化是属性**偏移直取**的前提,支柱②的终态)。

## 2. 现状速览(v1,已核实)

- **写入点恰好 8 处,无隐藏站点**:运行时 1 处初始化(`_object_new` object/index.js:294-295 恒 0)+
  4 处置 0(delete :1593-1595 / 追加新键 :2057-2060 / setPrototypeOf :3407-3410 / 整数键重排
  :4048-4050);编译器 3 处戳入(字面量 data_structures.js:456、类实例 expressions.js:1121/1176)。
- **描述符**:数据段 per-site(字面量)/per-class memo(类),内容仅 key_count;运行时从不解引用,
  **只做指针身份比较**(IC 快路 :1113-1115 / :1402-1403)。
- **IC 槽**(数据段,get 24B {shape,holder,index} / set 16B {shape,index}):首触必 miss 回填;
  单槽多态互踢;深链委托不缓存;键自验证单 cmp **全程保留**(消除实测零增益,且是跨模块
  同名类 memo 误配的兜底——v2 必须继续保留)。
- **键契约**:串键 = 0x7FFC 装箱驻留串(指针身份);数值键经 `_js_prop_key` 归一十进制串;
  symbol 键裸指针。v2 转移边标识**必须沿用 boxed 驻留键身份**,不引入第二套键表示
  (plan.md:77 键表示分裂事故:慢路簇 6%→12% 的真实教训)。
- **byte1 扩展位**(freeze/seal/nonext/HASFLAGS)强制 IC set 落慢路——v2 不得绕过 attrs 慢判。

## 3. v2 模型:静态描述符 + 堆转移节点共存

**不移除 v1 静态描述符**(字面量/类的编译期形状零成本、已生效)。新增第二层:

- **转移节点**(堆分配,32–48B,走既有 size-class 通道,无专用分配器):
  `{ parent_shape_ptr, key_count, new_key(boxed 驻留), new_index, transitions_ptr }`。
  全局共享(同一路径的对象复用同一节点),稳态分配率 ≈ 0。
- **转移表**(side table,不以节点内嵌为唯一存储):`(from_shape, key) → to_shape`。
  from_shape 可以是**数据段静态描述符**——静态描述符不可写(引擎片段 RX 先例,且数据段
  直存最省 GC 误判面),故转移边一律存 side table,不写描述符本体。
  表根:**数据段锚槽**(仿 `_global_this`,allocator.js:4386-4389),自动被数据段根扫描覆盖。
- **shape_ptr@48 三态**:0 = 无形状(legacy);数据段址 = 静态描述符(v1);堆址 = 转移节点(v2)。
  IC 快路的指针比较对三态统一成立,槽布局**不改**(24B/16B 已固)。
- **转移语义(仅加键)**:对象(形状 S)加新键 k → 查 (S,k):命中 → shape_ptr = S'(同 S 的
  所有对象共享此边,属性 index 布局一致);未命中 → 建 S'(new_index = S.key_count,追加写),
  记边。键已存在(更新值)不转移。
- **delete / setPrototypeOf / 整数键重排:维持置 0**(delete 整体下移 kv,缓存 index 处换键,
  正确性依赖键自验证——改成"删除转移"要同步处理站点旧 index 假命中,收益不抵风险;
  setPrototypeOf 置 0 还兼 holder 缓存失效,保守正确)。
- **symbol 键/计算键加键:维持置 0**(不走转移)。
- **megamorphic 退化(必设)**:单个形状转移边数超阈(建议 16)→ 标记 MEGAMORPHIC →
  该形状后续加键一律置 0。防字典模式路径爆炸(每对象独占形状链 → 分配量与对象数同阶)。
  退化是**形状级**而非对象级,天然共享。

## 4. GC 交互(存活性已安全,两条铁律)

调研结论:**现有保守 GC 对形状堆实体的存活性零改动即安全**——
- shape_ptr@48 堆→堆指针:对象头 56B 恒在 `_gc_drain` 整块扫描面内(:3260-3305)✓
- IC 槽 obj_shape@0 堆指针:落 [_data_start, _data_gc_end) 数据段根扫描(full + minor 均扫)✓
- 转移节点互指(parent/子):堆→堆,drain 覆盖 ✓
- 转移表根:数据段锚槽,自动覆盖 ✓(勿引入精确标记)

**铁律 1 — old→young 屏障**:sticky minor 不重扫 old 对象(:1758-1761)。一切**对已有对象
写 shape_ptr@48** 的路径(转移命中、编译器戳入点)必须经含 `_gc_remember`(:2305)的
统一 store helper(old 对象写 young shape 记入 RS,否则 minor 漏标 → sweep_young 回收活
shape → UAF)。现存 3 个编译期戳入点写数据段址在 v1 免屏障,堆化后**不再免**。
收口方案:所有 @48 写走 `_shape_store(obj, shape)` helper(判 old/young 登记)。

**铁律 2 — helper 寄存器契约**:转移查/建 helper 内部调 `_alloc`(可触发 GC!),调用者的
obj/shape 裸指针只在寄存器/栈。新 helper 必须遵守 runtime-helper-reg-contracts(只存
S0–S4、scratch V0–V4),跨 _alloc 的活值存 S 寄存器——写新运行时的头部铁律。

**@48 仲裁(与 GC_COMPACTION_DESIGN 的硬冲突)**:压实方案 §6.2 预定借 @48 做 forwarding
word,判别依据"∈数据段=形状 / ∈堆=forwarding"——shape 堆化**直接摧毁该判别**。
**本设计的裁决:shape v2 先行,压实 forwarding 改走 §6.3 位图判活通用方案**
(理由:@48 复用是压实三方案中较脆的一个,位图判活本就已列为通用后备;shape v2 的
收益面(方法读/字典形态)大于压实省下的判别简并)。需同步更新 GC_COMPACTION_DESIGN
§6.2 与 Q10。**两专项不得各自假定 @48 语义而不同步。**

**压实修补归类(预备)**:shape_ptr@48 = A 类(头字段自修补);IC 槽 = C 类(ic_site 表停世界
扫改,§8 阶段 2 已规划);转移节点 = A 类(按布局自修补 parent/transition/key)。

## 7.5 T0/T2a 落地实测(2026-07-22,arch/efficiency)

**已落地**:T0(转移节点 + 转移表 + 锚槽,惰性)、T2a(原型运行时赋形:
TYPE_SHAPE_DESC 堆描述符,键表 = proto props 键列运行时快照;IC miss 路径
`_ogic_pkey_*` 键表单 cmp 查 index 替代 kv 指针追扫)。fixtures 380/380
(新增 8 个 shape-proto-* 簇),arm64 + x64 全绿。

**x64 实证坑(入库)**:x64 后端 **V0 与 RET 同物理寄存器**——_alloc 返回值
在 RET 中,其后任何 V0 运算(如 `mov V0, S3` / `subImm V0, RET, 16`)直接覆盖
描述符/表指针,store(RET,…) 写垃圾地址 SIGSEGV。规约:_alloc 后若还需 RET,
中间值一律用 V2+(或立即落锚/存 S 寄存器);and 只用 dest==a 形态。

**负结果(实测诚实记录)**:T2a 对两类实测负载**均无可测收益**:
- 方法调用微基准(100M × 3 方法):1.51s → 1.50s(node 0.07s,差距 ~22× 不变);
- 自编译热图:慢路簇 _ogic_slow_getter 2.7%→2.5%、ptrscan 1.8%→1.9%、
  check_proto 1.2%→1.4%——统计噪声内;`_ogic_pkey_*` 新标签几乎零采样。

**归因**:IC 站点首触 miss 回填后,后续读取全走**命中路径**(holder+index 直取),
miss 是每站点一次性事件;慢路簇采样主体其实是命中路径的 getter 检查尾跳落点
(_ogic_slow_getter 兼作命中路径 getter dispatch 标签),不是 miss 扫描。
⟹ **查找/形状优化已到收益递减点;剩余差距的主体是命中路径机制本身**:
每访问一次 bl/ret 往返(零 prologue 快路仍是函数调用,V8 内联为单 ldr)+
getter 检查(微基准 14.9% 叶采样)+ 装箱往返。

**战略修订**:T1(转移链)的价值收窄为"字典形态负载的覆盖面"(我们自己的
benchmark 与自编译均非此类);下一批真正的杠杆候选(按风险/收益):
① T2b getter 检查消除(需 defineProperty 零化 + 站点失效协议,中等风险,
   微基准 ~5-10%);② 命中路径内联(支柱②终态,受"产物 +54%"铁案约束,高风险);
③ 解箱/装箱削减(支柱①续);④ T1 转移链(字典负载覆盖,低优先)。

**T2b 证伪(实测)**:命中路径 getter 检查短路(测量专用,未提交)→ method_bench
1.52s vs 1.51s、prop 0.28 vs 0.31——**零差异**。14.9% 叶采样是调用边界聚集假象,
检查指令本身无成本。T2b 废弃(省去失效协议的投资)。

**命中路径内联 POC 证伪(实测)**:IC 读快路(自有键+原型键两路,镜像 helper
零 prologue 序列,守卫失败落 bl;x64 寄存器纪律:仅 V0/V1/V3/V4,避 V2=A2/V7=A1
别名)站点内联,fixtures 380 + x64 全绿,但:
- 时延:method_bench 1.51s vs 1.50s(非内联)、prop 0.27-0.28 vs 0.29——**零差异**;
- 产物:cli.js 自编译 **44.3MB vs 18.2MB(+144%)**,远超 +54% 铁案红线。
归因:arm64 分支预测 + 零 prologue helper 使 bl/ret 本身廉价;内联省的往返被
I-cache 压力吞没。**已回退**。

**阶段结论(本专项收尾)**:查找/形状/检查/调用机制四条优化路径全部实测穷尽,
当前架构下微基准收益井已枯。剩余 ~22× vs Node 的成本主体是**装箱往返 +
运行时类型分派**(如 _js_add 每次加法分派),唯一架构级杠杆是支柱① v2
(形状驱动的值类型化 → 属性算术解箱),属大型设计项目;或接受 AOT 层级性能,
把精力转回 plan.md 北极星(test262 覆盖率,20.55% → 目标 40%)。
